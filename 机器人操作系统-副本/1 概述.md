# 1 概述
## 机器人硬件组成
- 信息感知：智能机器人通过内部传感器实现自身状态感知，同时借助外部传感器获取环境信息
	- 内部传感器（自身感知）
		- 位置、位移、角度传感器
		- 速度、加速度传感器
		- 力觉传感器

		- 视觉传感器
		- 触觉传感器
		- 声觉传感器
		- 滑觉传感器
- 决策控制：由控制计算机处理感知数据并生成行为指令
	- 通用计算机
	- 嵌入式计算机
	- 高性能单片机
- 驱动装置：包含能量转换装置及驱动电机，负责将控制信号转化为机械运动
- 机械结构：承载传感器、驱动与控制系统的实体框架，构成机器人物理形态

# 2 功能包
## ROS2的层次架构
![[机器人操作系统-副本/assets/Pasted image 20251210141302.png]]
- **工作空间**： 是开发ROS项目的顶层目录，包含所有功能包、编译文件和安装文件。
    
- **功能包**： 是工作空间中的基本功能单元，对应一个特定功能的文件夹）、。一个工作空间可以包含多个功能包。
    
- **节点**： 是功能包中可执行的进程。一个功能包可以包含多个节点，每个节点负责完成一个具体的任务。
## 工作空间的结构
- src/： 源代码空间。用户在这里创建和存放所有功能包的源代码。
- build/： 编译空间。colcon工具存储缓存信息、配置参数和中间编译文件的地方。
- install/： 安装空间。构建成功后，生成的可执行文件、库文件和脚本都会安装到此目录。
- log/： 日志空间。存储构建过程中的日志信息。

常用命令：
```shell
新建工作空间目录
mkdir -p ./ros_workspace/src

构建功能包
colcon build
构建过程中，当前目录下会产生build、install和log目录
	符号链接构建（用路径符号代替实体文件）：
	colcon build --symlink-install
	
	只构建指定包：
	colcon build --packages-select <package_name>
	构建指定包及其相关包：
	colcon build --packages-up-to <package_name>
```

```python
# 导入ROS2客户端库
import rclpy
# 导入Node基类，所有节点都需要继承此类
from rclpy.node import Node
# 导入标准消息类型String
from std_msgs.msg import String

class DemoPublisher(Node):
    """发布者节点类，用于定期发布消息到指定话题"""
    
    def __init__(self):
        """
        节点初始化函数
        - 创建节点名为'my_publisher'
        - 创建发布者对象，话题名为'chd_topic'，队列大小为10
        - 创建定时器，每0.5秒触发一次回调函数
        """
        # 调用父类构造函数，设置节点名
        super().__init__('my_publisher')
        
        # 创建发布者对象：
        # - String: 消息类型（标准字符串消息）
        # - 'chd_topic': 话题名称（其他节点通过此名称订阅）
        # - 10: 队列大小（缓存的消息数量）
        self.publisher_chd = self.create_publisher(String, 'chd_topic', 10)
        
        # 设置定时器周期为0.5秒
        timer_period = 0.5  # seconds
        
        # 创建定时器：
        # - timer_period: 定时器周期（秒）
        # - self.timer_callback: 定时器到期时的回调函数
        self.timer_chd = self.create_timer(timer_period, self.timer_callback)
        
        # 初始化消息索引计数器
        self.index = 0
        
        # 在日志中输出初始化完成信息
        self.get_logger().info('DemoPublisher节点初始化完成，开始发布消息...')

    def timer_callback(self):
        """
        定时器回调函数
        - 每0.5秒自动执行一次
        - 创建并发布消息到'chd_topic'话题
        - 在日志中记录发布的消息内容
        """
        # 创建String类型的消息对象
        msg = String()
        
        # 设置消息内容：包含问候语和当前索引
        msg.data = f'Hello World and CHD: index={self.index}'
        
        # 发布消息到'chd_topic'话题
        self.publisher_chd.publish(msg)
        
        # 在日志中记录发布的消息内容（INFO级别）
        self.get_logger().info(f'Publishing: "{msg.data}"')
        
        # 索引自增，为下一条消息准备
        self.index += 1

def main(args=None):
    """
    主函数：节点的主要执行流程
    """
    # 初始化ROS2客户端库，必须首先调用
    rclpy.init(args=args)
    
    try:
        # 创建发布者节点实例
        demo_publisher = DemoPublisher()
        
        # 进入ROS2事件循环，保持节点运行并处理回调
        # spin()会阻塞直到节点被关闭
        rclpy.spin(demo_publisher)
        
    except KeyboardInterrupt:
        # 捕获Ctrl+C中断信号
        demo_publisher.get_logger().info('收到中断信号，节点正在关闭...')
    except Exception as e:
        # 捕获其他异常
        demo_publisher.get_logger().error(f'节点运行出错: {e}')
    finally:
        # 清理资源：销毁节点
        if 'demo_publisher' in locals():
            demo_publisher.destroy_node()
        
        # 关闭ROS2客户端库
        rclpy.shutdown()

# Python标准的主程序入口
if __name__ == '__main__':
    main()
```

```python
        self.get_logger().info(f'I heard: "{msg.data}"')

        # 进入ROS2事件循环，保持节点运行并处理回调
        # spin()会阻塞直到节点被关闭，期间会监听到来的消息
        rclpy.spin(demo_subscriber)
        
    except KeyboardInterrupt:

        if 'demo_subscriber' in locals():
            demo_subscriber.destroy_node()
            demo_subscriber.get_logger().info('节点资源已清理')
        
        # 关闭ROS2客户端库
```

## 节点的命名空间、重命名
### 命名空间namespace
将命名分组储存，便于管理，允许不同命名空间中存在重名。

默认的命名空间是根目录，即'/'

命名空间路径的重映射方法：
`ros2 run <package-name>  <executable>  --ros-args --remap __ns:=<new-ns>`
\<executable\>填要被重命名的空间名
\_\_ns代表这里重命名的是namespace，下面的__node等同理
### 节点重命名
`ros2 run <package-name>  <executable>  --ros-args --remap __node:=<new-node-name>`

如果要同时重命名命名空间和节点：
`ros2 run <package-name>  <executable>  --ros-args --remap __ns:=<new-ns>--remap __node:=<new-node-name>`
### 话题重命名
`ros2 run <package-name>  <executable>  --ros-args --remap <old-topic-name>:=<new-topic-name>`

> 为了只针对特定功能包进行构建，可以使用哪些构建选项，这些选项有什么区别？

可采用构建选项：--packages-select或--packages-up-to进行构建，前者只构建指定包，不会处理其依赖的包；后者会递归构建所有依赖，将所有相关的功能包同步更新。
如`colcon build --packages-select <package_name>`

> 构建选项中的—symlink-install的作用是什么？

该选项能够在安装目录通过符号链接的方式指向二进制文件和资源文件，减少了默认没有该选项产生的文件I/O操作，更重要的是符号链接直接指向源码文件，更改python源码和资源文件无需重新构建，提升了调试效率。

# 4 Launch
## 意义
- 无须手动多次进行ros2 run，一键启动要运行的东西
  `ros2 launch [<package-name>] <launch-file-name>`
- 可设置启动条件、设置节点参数、设置环境变量
- 可包含其他 launch 脚本
- 应位于src/\<package\>/launch中

会涉及到.py .xml .yaml格式文件
## 基本格式
- 导入LaunchDescription类
```python
from launch import LaunchDescription
```
- 进行全局常量、函数、工具定义
- 定义回调函数（就是launch启动过程中跑的函数）
```python
def generate_launch_description( ):
```
- 在回调函数中，写所有需要进行的动作，如启动节点（使用Node类）等，这些动作称为actions
- 返回LaunchDescription对象，括号里面装刚才定义的 actions
```python
return LaunchDescription([ … ])
```

### 使用launch文件启动Node节点
- 导入所需的类
```python
from launch import LaunchDescription
from launch_ros.actions import Node
```
- 在回调函数generate_launch_description()中生成node实例
```python
def generate_launch_description( ):
      <node-ins>=Node(<初始化列表参数>)
```
	列表参数要有：
	•package='<package-name>'功能包名
	•executable='<executable-name>'可执行文件名

```python
# 导入ROS 2启动系统所需的模块
from launch import LaunchDescription  # 用于构建启动描述的主要类
from launch_ros.actions import Node   # 用于创建ROS节点动作
from launch_ros.parameter_descriptions import ParameterValue  # 参数值描述类
from ament_index_python import get_package_share_directory  # 获取ROS 2功能包路径
from launch.substitutions import Command  # 用于执行shell命令的替换类

# ROS 2启动文件的入口函数，必须命名为generate_launch_description
def generate_launch_description():
    # 【步骤1】获取机器人描述功能包的共享目录路径
    # 通过包名'myrobot_description'自动定位到该包的安装路径
    pkg_share_dir = get_package_share_directory('myrobot_description')
    
    # 【步骤2】拼接URDF模型文件的完整路径
    # 假设URDF文件位于包的urdf子目录下，文件名为myrobot.urdf
    urdf_file = pkg_share_dir + '/urdf/myrobot.urdf'
    
    # 【步骤3】处理URDF/Xacro文件
    # 使用xacro工具解析URDF文件（支持xacro宏和变量扩展）
    urdf_string = ParameterValue(
        # Command用于执行shell命令：'xacro 文件路径' 将xacro转换为URDF字符串
        Command(['xacro ', urdf_file]),
        value_type=str  # 明确指定返回值为字符串类型
    )
    # 此时urdf_string包含了机器人模型的完整URDF描述（已解析的字符串形式）
    
    # 【步骤4】创建robot_state_publisher节点
    # 这是ROS 2中负责发布机器人状态的核心节点
    robot_state_publisher_node = Node(
        package='robot_state_publisher',       # 节点所属的ROS包名
        executable='robot_state_publisher',    # 要执行的可执行文件名
        parameters=[{                           # 传递给节点的参数列表
            # 关键参数：将解析后的URDF模型字符串传递给节点
            'robot_description': urdf_string
        }]
    )
    # robot_state_publisher节点的作用：
    # 1. 从robot_description参数读取完整的URDF机器人模型
    # 2. 订阅/joint_states话题（获取各关节的实时状态）
    # 3. 发布/tf和/tf_static话题（计算并发布所有坐标系间的变换关系）
    # 4. 让RViz等可视化工具能够正确显示机器人模型及其运动
    
    # 【步骤5】构建并返回启动描述
    # 创建包含所有要启动节点的LaunchDescription对象
    return LaunchDescription([
        robot_state_publisher_node  # 将节点添加到启动列表中
    ])
```

## XACRO
全称：可扩展标记语言(XML)宏(macro)
### 概述
优点：
- 更短小、更易读、便于复用代码（模块化）
- 提供编程接口(常量、变量、数学公式或条件语句)，增强XML的表达力
特点：
- 需要xacro工具对.xacro进行解析
### 三大核心语法
#### \<xacro:property>常量
定义可重复用的，统一修改复制的常量值

例程：
```xml
<!-- 定义常量 -->
<xacro:property name="wheel_radius" value="0.1" />
<xacro:property name="body_length" value="0.5" />
<xacro:property name="pi" value="3.14159" />

<!-- 使用常量 -->
<link name="wheel">
  <visual>
    <geometry>
      <cylinder length="0.05" radius="${wheel_radius}"/>
    </geometry>
  </visual>
</link>
```
#### \<xacro:macro>宏定义
将部件定义为可重复使用的宏，类似函数。

例程：
```xml
<!-- 定义一条机器腿的宏 -->
<xacro:macro name="robot_leg" params="prefix parent_link reflect">
  <link name="${prefix}_leg">
    <visual>
      <geometry><cylinder length="0.3" radius="0.05"/></geometry>
    </visual>
  </link>
  
  <joint name="${parent_link}_to_${prefix}_leg" type="fixed">
    <parent link="${parent_link}"/>
    <child link="${prefix}_leg"/>
    <origin xyz="0 ${0.2*reflect} 0.15"/>
  </joint>
</xacro:macro>

<!-- 使用宏实例化两条腿 -->
<xacro:robot_leg prefix="left" parent_link="base_link" reflect="1"/>
<xacro:robot_leg prefix="right" parent_link="base_link" reflect="-1"/>
```

将机器人的不同部分拆分到不同文件，有一个主文件负责组装

例程：
```xml

  <xacro:include filename="$(find myrobot_description)/urdf/pebble_gripper.xacro"/>

  <!-- 底盘基础结构 -->
  <link name="base_link">...</link>

  <!-- 实例化组件 -->
  <xacro:pebble_leg base_link_name="base_link" prefix="left" reflect="1"/>
```

以上步骤的各个函数应用了若干和TF相关的重要的类，包括：

（1）static_transform_publisher：

能够发布两坐标系之间的静态变换关系/tf_static，即实现了turtle1后、左、右三处坐标id和turtle1自身坐标id的静态变换关系。

（2）TransformBroadcaster：

其中的sendTransform方法能够发布两坐标系的动态变换关系/tf，即实时发布乌龟坐标和世界坐标之间的变换关系/tf。

（3）TransformListener：

通过内嵌的缓存对象的lookup_transform方法计算两坐标系id之间的变换关系，即通过计算护卫坐标id到护卫乌龟id之间的变换关系，以便计算生成/cmd_vel话题控制护卫乌龟运动。

备注，为了避免给同学们带来困扰，以上没有用“目标坐标id”这个词语，因为在此应用中，lookup_transform函数中的参数名“target_frame”取值是护卫乌龟的id，并不是乌龟要运动到的目的地坐标id。
